- [DONE] Update directly (Download and install from the app, not just pointing to GitHub to download the new version)
  -> In-app download/mount/install/relaunch flow (SelfUpdateService.swift). Round 2 fix
  (signature verification + quarantine-clearing) turned out not to be the actual bug —
  round 3 feedback correctly called this out ("app doesn't quit, possibly the sheet is
  interfering") and that was exactly it: UpdateNotificationView is presented via .sheet()
  on the main window (TabManager.swift), and NSApp.terminate(nil) can't cleanly quit while
  a window still has an attached sheet — the app just sits there, which looks identical to
  a hang. Fixed by explicitly ending every window's attached sheet and closing the windows
  directly before calling terminate (SelfUpdateService.quitForRelaunch()), with a short
  delay so that actually takes effect first. Also hardened the installer script: it now
  aborts (leaves everything in place) if the old process is somehow still alive after the
  30s wait, instead of proceeding to swap files out from under a live process. Also added a
  "No release notes were provided for this update" fallback for the empty What's New case.
  Round 4: the update DID work after the round-3 fix, but with a visible close/reopen/close
  flicker on the sheet right before quitting — caused by quitForRelaunch() ending the sheet
  directly at the AppKit level while SwiftUI's own @State-driven .sheet(isPresented:)
  binding (TabManager.swift) still thought it should be showing, so SwiftUI tried to
  re-present it. Fixed by having TabManager dismiss the sheet itself (through its own
  binding) as soon as it observes stage == .relaunching, and having quitForRelaunch() just
  wait long enough for that real dismissal to finish before calling NSApp.terminate --
  only one thing drives the sheet now. Round 4 also answered "does accessibility permission
  survive updates?": yes, for a properly signed release, because macOS ties the grant to
  (bundle ID + signing team), not the file/path, and the update swaps the bundle in place
  keeping both identical. Added a bundle-identifier match check alongside the existing
  signature/team check as extra insurance (if it doesn't match, this isn't really "the same
  app" and shouldn't auto-install as an update regardless of permissions).
  Also redesigned the update source per round 2: pulls live from GitHub's
  release API (api.github.com/repos/.../releases/latest) instead of a hand-maintained
  version.json (deleted) — matches the pattern Website/js/main.js's own release lookup
  already used, so there's nothing to forget to update after cutting a release.
