[Also fixed while working through this list: a pre-existing crash (present before
any of these changes) where Configuration.performSave() dispatched onto saveQueue
and then writeConfigurationToDisk() called saveQueue.sync from inside that same
block — a guaranteed libdispatch deadlock/crash ("dispatch_sync called on queue
already owned by current thread"). This is what was crashing the app once

debounced config save). Fixed in Configuration.swift by hopping onto a separate

- [DONE] Update directly (Download and install from the app, not just pointing to GitHub to download the new version)
  -> In-app download/mount/install/relaunch flow (SelfUpdateService.swift). Round 2: the
  first version got stuck on "Relaunching" with a failure sound — root cause was almost
  certainly Gatekeeper silently blocking the freshly-copied app after the old one had
  already quit (nothing left running to show an error). Fixed by verifying the downloaded
  app's code signature (and Developer ID team match, when this build itself is signed)
  BEFORE quitting, so a bad update fails with a clear on-screen message instead of hanging,
  and by clearing the quarantine flag on the swapped-in copy so Gatekeeper doesn't block
  the relaunch. Also redesigned the update source per round 2: pulls live from GitHub's
  release API (api.github.com/repos/.../releases/latest) instead of a hand-maintained
  version.json (deleted) — matches the pattern Website/js/main.js's own release lookup
  already used, so there's nothing to forget to update after cutting a release.
