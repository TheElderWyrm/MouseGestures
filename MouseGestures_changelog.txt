## 2026-01-20

### Bug Fixes
- Fixed EXC_BAD_ACCESS crash when toggling zone highlights setting
  - Root cause: isReleasedWhenClosed = true caused window to self-deallocate while manager still held reference
  - Autorelease pool drain would then try to release already-deallocated object
  - Changed to isReleasedWhenClosed = false with explicit lifecycle management

### Memory Optimizations
- Reduced idle memory usage from ~125 MB toward 45-65 MB target
- **Zone Highlights: Replaced full-screen window with individual zone windows**
  - Full-screen backing store was ~60 MB on Retina (5120x3200 × 4 bytes)
  - Now uses 8 small windows, one per zone (~1-2 MB total)
  - New ZoneWindow/ZoneView classes for lightweight per-zone rendering
- AppDelegate: Removed hidden SettingsActionHandler NSWindow that was keeping SwiftUI layers alive
  - Now finds and triggers Settings menu item directly, with Cmd+, fallback
- TabManager: Implemented lazy tab loading with LazyTabPlaceholder
  - Only renders tabs when first selected instead of all 8+ at startup
  - Prevents CoreAnimation layer explosion from pre-rendering all views
- ZoneHighlightWindow: Fixed lifecycle for proper memory release
  - Uses isReleasedWhenClosed = false with explicit lifecycle management by ZoneHighlightManager
  - Made highlightView optional with weak references in closures
- ZoneHighlightManager: Improved observer cleanup
  - Store screen change observer reference for proper cleanup
  - Added comprehensive cleanup() method in deinit
  - Close old window before creating new one on screen change

### New Features
- Implemented ActivationCoordinator for efficiency-based detector gating
  - New `ActivationType` enum with efficiency scores (0-100) for each detection type
  - `ActivationCoordinator` singleton manages activation states across all plugins
  - `ActivationProvider` protocol for plugins to declare their activation capabilities
  - Dependency graph auto-built by analyzing gesture configurations
  - Low-efficiency detectors (screenZone: 20) gated behind high-efficiency ones (modifierKey: 100)
  - Fully generalizable: any new plugin can participate in the efficiency system
  - Removes hardcoded coupling between ModifierKeyDetector and ScreenZoneDetector
  
- All detection plugins now implement ActivationProvider:
  - ModifierKeyDetectorPlugin: provides `.modifierKey` activation
  - ScreenZoneDetectorPlugin: provides `.screenZone` and `.mouseDrag` activations
  - KeyboardShortcutDetectorPlugin: provides `.keyboardShortcut` activation
  - MouseButtonDetectorPlugin: provides `.mouseButton` activation  
  - AppConfigurationDetectorPlugin: provides `.appChange` activation

- Implemented plugin-based settings system for detection plugins
  - New `PluginSettingDefinition` struct for declaratively defining plugin settings
  - Settings types: toggle, slider, stepper, picker, segmented picker, color, text, button, info
  - Support for setting dependencies (show setting B only when setting A is enabled)
  - Support for setting validation with error messages
  - Settings are persisted in Configuration and loaded on app launch
  
- Updated all built-in detection plugins with configurable settings:
  - ScreenZoneDetectorPlugin: edge threshold, corner size, corner buffer, zone highlights, tracking rate
  - ModifierKeyDetectorPlugin: cooldown enable/disable, cooldown duration
  - KeyboardShortcutDetectorPlugin: double-tap prevention, prevention interval
  - MouseButtonDetectorPlugin: require modifiers, allowed buttons filter
  - AppConfigurationDetectorPlugin: auto-switch profiles, haptic feedback, app history size
  
- Added new "Detection" section in Settings UI
  - PluginSettingsView renders all plugin settings dynamically
  - Settings grouped by category (Detection, Appearance, Performance, etc.)
  - Show/hide advanced settings toggle
  - Real-time updates with dependent settings visibility
  
- DetectionPluginManager now handles settings persistence:
  - `getAllSettingsDefinitions()` - get all settings from all plugins
  - `updatePluginSetting()` - update and persist a single setting
  - `resetPluginSettings()` - reset all settings for a plugin

### Bug Fixes
- Fixed unreliable gesture detection when modifiers are already pressed at startup
  - Issue: If user held modifier keys before detection started, gestures wouldn't trigger
    until modifiers were released and re-pressed
  - Root cause: `flagsChanged` events only fire on modifier state *changes*, not when
    modifiers are already held
  - Fix: Both ModifierKeyDetectorPlugin and ScreenZoneDetectorPlugin now check current
    system modifier state on startup via `NSEvent.modifierFlags`
  - ModifierKeyDetectorPlugin initializes its internal state if modifiers are already held
  - ScreenZoneDetectorPlugin enables mouse tracking immediately if modifiers are pressed

- Fixed gesture detection using stale cached modifier state
  - Changed `detectGesture()` to use real-time system modifiers via 
    `ModifierKeyDetectorPlugin.currentSystemModifiers()` instead of cached plugin state
  - Prevents missed gestures due to timing lag between system events and plugin state

- Fixed gestures not triggering when mouse is stationary in zone and modifiers are pressed
  - Added `checkCurrentMousePosition()` that runs when mouse tracking is enabled
  - If mouse is already in a zone when modifiers are pressed, gesture now triggers immediately

- Fixed gestures not re-triggering when modifiers change while mouse is in zone
  - ScreenZoneDetectorPlugin now monitors modifier changes directly
  - When modifiers change and mouse is in a zone, re-checks for matching gesture
  - Added `lastTriggeredModifiers` tracking to detect modifier-only changes
  - Allows different gestures for same zone with different modifier combinations

## 2026-02-05

### Bug Fixes - Efficiency Mapping
- **Fixed efficiency mapping not working - CPU rises when mouse moved regardless of modifiers**
  - Root cause: Race condition in ActivationCoordinator's disabling logic. When modifiers were 
    released, the screen zone detection reported as "engaged" if `lastTriggeredZone != nil`, 
    preventing the coordinator from disabling mouse tracking. The mouse event monitor stayed 
    active and processed events even with early returns, causing unnecessary CPU usage.
  - Fix: ScreenZoneDetectorPlugin now listens for modifier state changes via NotificationCenter.
    When all modifiers are released, it immediately clears `lastTriggeredZone` and notifies the
    coordinator that screen zone detection is disengaged. This allows the coordinator to properly
    disable mouse tracking, stopping event processing.
  - ModifierKeyDetectorPlugin now posts `ModifierStateChanged` notification after each modifier
    change, allowing other plugins to react immediately to modifier state transitions.
  - Impact: Mouse tracking now properly disables when modifiers are released, eliminating 
    unnecessary CPU usage during normal mouse movement without modifiers held.

### Bug Fixes - Zone Highlights
- **Fixed zone highlights getting stuck when modifiers released during certain actions**
  - Issue: Zone highlights could remain visible after modifiers were released if an action like
    entering fullscreen interrupted the normal event flow. The ZoneHighlightManager relied solely
    on flagsChanged events, which could be missed during window state transitions.
  - Fix: Added multiple safeguards to ensure highlights are properly hidden:
    - ZoneHighlightManager now listens for ModifierStateChanged notifications from 
      ModifierKeyDetectorPlugin, providing a secondary path for detecting modifier releases
    - Added observers for NSApplication.didResignActiveNotification to hide zones when app 
      loses focus
    - Added observers for NSWindow.willEnterFullScreenNotification to hide zones before 
      fullscreen transitions
  - Impact: Zone highlights now properly disappear in all scenarios, preventing them from 
    getting stuck on screen during fullscreen transitions or other window state changes.

## 2026-02-06
### Bug Fixes - Efficiency Mapping (actual fix)
- **Fixed mouse tracking staying permanently active after any drag event**
  - Root cause: handleMouseDrag() called enableMouseTracking() directly, bypassing the
    ActivationCoordinator. When drag ended, handleMouseUp() relied on the coordinator to
    disable tracking, but since the coordinator never added .screenZone to its enabledTypes,
    disableActivationType() exited early at the guard. Mouse tracking stayed active forever.
  - The previous fix (2026-02-05) addressed the coordinator-side issue of screenZone reporting
    as engaged, but did not address the direct enableMouseTracking() call in handleMouseDrag().
  - Fix: Added mouseTrackingEnabledByDrag flag to track when drag directly enables tracking.
    handleMouseDrag() now only enables tracking if drag-based gestures actually exist
    (via new hasDragGestures() helper). handleMouseUp() explicitly disables tracking when
    the coordinator would not keep it active, closing the lifecycle gap.
  - Impact: Mouse tracking now correctly stays disabled during normal mouse movement.
    CPU usage drops to 0% when no modifiers are held and no drag gestures are active.

### Code Quality
- Removed all diagnostic [DIAG] print statements from ActivationCoordinator and
  ScreenZoneDetectorPlugin that were added to debug the efficiency mapping issue.
