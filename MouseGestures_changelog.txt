## 2026-02-24

**Fix: Modifier key interference when gesture triggers use modifier keys**
- Gestures activated with modifier keys (e.g. Ctrl+drag) caused held modifiers to
  bleed into the action's keyboard shortcuts (e.g. switch spaces, App Exposé)
- Root cause: Gesture-trigger modifier keys are still physically held when the action
  fires. Synthetic key-up events cannot override hardware state. AppleScript/System
  Events (the only reliable mechanism for system shortcuts like Ctrl+Arrow) sees the
  extra physical modifiers and the shortcut is contaminated.
- Fix: Added `waitForModifierRelease()` that polls `CGEventSource.flagsState(.hidSystemState)`
  (thread-safe, reflects actual HID hardware state) until ALL modifier keys are released.
  Requires two consecutive clean reads ~20ms apart to avoid false positives from
  sequential key releases (e.g. user lifts Ctrl before Cmd). Checks three state
  sources (HID, combined session, AppKit) for reliable detection. Called only in
  the specific actions that need it (`moveToSpace`, `activateAppExpose`) — not
  globally in the sandbox, so other actions (fullscreen, etc.) execute immediately.
  Kept AppleScript/System Events for those two actions. CGEvent `.privateState`
  for app-level shortcuts.

### Refactor: Removed Gesture-Awareness from Detection Plugins
- **Problem**: Detection plugins were violating single responsibility by understanding
  gesture structure through `gestureUsesActivation()` method. Plugins had to inspect
  gesture fields (modifiers, dragModifier, activation types) to determine if they
  were needed, creating tight coupling between detection layer and gesture configuration.
- **Solution**: Introduced **ActivationMapper** — a central service that understands
  gesture structure and maps gesture properties to activation types.
- **Changes**:
  * New file: ActivationMapper.swift containing all gesture→activation mapping logic
  * ActivationCoordinator now uses ActivationMapper instead of asking plugins about gestures
  * Removed `gestureUsesActivation()` from ActivationProvider protocol
  * Removed `validateGate()` from ActivationProvider protocol
  * Added `getGateValidationMetadata()` to ActivationProvider protocol
  * Plugins now only provide detection metadata, not gesture interpretation
  * Precision gate validation moved to coordinator using mapper
- **Refactored Plugins**:
  * ModifierKeyDetectorPlugin: Removed gesture inspection, provides modifier state metadata
  * MouseButtonDetectorPlugin: Removed gesture inspection, provides button state metadata
  * ScreenZoneDetectorPlugin: Removed gesture inspection
  * KeyboardShortcutDetectorPlugin: Removed gesture inspection
  * AppConfigurationDetectorPlugin: Removed gesture inspection
- **Benefits**:
  * True separation of concerns: plugins detect, mapper interprets
  * Reduced coupling: plugins don't depend on Gesture structure
  * Better testability: clear boundaries for unit tests
  * Easier maintenance: all gesture interpretation in one place (ActivationMapper)
  * Changes to Gesture fields only affect mapper, not all plugins
- **Note**: Internal plugin optimizations (like checking if drag gestures exist before
  installing monitors) are still fine — that's implementation detail, not architectural
  responsibility violation. The key improvement is that plugins no longer need to
  understand *what makes a gesture use their activation type*.
- **Follow-up Fix**: Discovered and fixed additional gesture structure inspection:
  * GestureLookup was checking `gesture.activationType` — now uses ActivationMapper
  * KeyboardShortcutDetectorPlugin was filtering by `gesture.activationType` — now uses ActivationMapper
  * MouseButtonDetectorPlugin was filtering by `gesture.activationType` — now uses ActivationMapper
  * ActivationMapper is now the **single source of truth** for all gesture→activation mapping
  * ZERO direct `gesture.activationType` checks remain in detection layer

## Bug Fixes and UI Improvements

### Fix: Quick Profile Switch Now Works
- **Problem**: Profile switching via gesture actions (Next Profile, Previous Profile, Switch to Profile)
  silently failed — profile didn't persist and UI didn't update.
- **Root Causes**:
  1. `SandboxedPluginContext.applyProfile()` called `Configuration.applyProfile()` without
     `setAsDefault: true`, so profile change didn't persist across sessions.
  2. Built-in plugin permissions blocked posting "GestureConfigurationChanged" notification,
     so UI never received the update signal after a switch.
- **Fixes**:
  * `SandboxedPluginContext.applyProfile()` now passes `setAsDefault: true`
  * Added "GestureConfigurationChanged" to `allowedNotificationsToPost` in builtIn permissions

### Fix: Preview Zones Button Shows Zone Names Regardless of Label Setting
- **Problem**: Preview zones button only showed labels when `showZoneLabels` was enabled globally.
- **Solution**: Added `forceShowLabel` flag to `ZoneView`. Preview mode sets this flag to always
  display zone names (e.g. "topLeft", "bottom") independently of the global `showZoneLabels` setting.
- Zone names are never replaced by action names during preview.

### Fix: Removed Duplicate Edit Button from Gesture Cards
- **Problem**: Expanded gesture cards showed two edit buttons — one in the hover actions row
  and another standalone "Edit" button in the expanded detail area.
- **Solution**: Removed the standalone Edit button from the expanded content area. The pencil
  icon in the row actions is sufficient.

### UI: Made Action Buttons Always Visible
- **Problem**: Edit, delete, and other action buttons on list rows were only visible on hover,
  making them hard to discover and inaccessible on trackpad-only setups.
- **Solution**: Removed `.opacity(isHovered ? 1 : 0)` from all row action buttons across:
  * GesturesView (gesture card row actions)
  * ProfilesView (profile list row actions, profile gesture row actions)
  * SavedActionsView (saved action row actions)
  * AppProfilesView (app mapping row actions)

### UI: Removed Zone/Haptic Settings from Profiles
- **Problem**: Zone detection settings (edge threshold, corner size, corner buffer) and haptic
  feedback toggle were shown per-profile, but these are global settings — not per-profile.
- **Solution**: Removed zone detection and haptic feedback controls from:
  * ProfileDetailEditor (inline editing view)
  * AddEditProfileSheet (create/edit profile dialog)
- These settings remain accessible in the global Settings tab.

### Fix: Reset to Defaults Now Only Affects Current Profile
- **Problem**: "Reset to Defaults" in the Gestures tab deleted ALL profiles and recreated
  them from templates — losing all custom profiles.
- **Solution**: `resetToDefaults()` now only replaces the active profile's gestures with
  the factory default gesture set. Other profiles remain untouched.
- Updated confirmation dialog text to reflect the new behavior.
